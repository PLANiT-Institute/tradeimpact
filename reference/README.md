# reference — what else measures this, and where TI sits against it

The Trade Impact framework is not the only attempt to say something about the climate
consequence of a product after it is sold, and it is not the first to subtract a counterfactual
from an emissions figure. This directory is the record of that surrounding work: what each
approach measures, what it publishes, and precisely where TI departs from it. It exists so that
a claim in the methodology can be traced to a document a reader can open, and so that the
objections are on file before a reviewer raises them.

| file | what it is |
|---|---|
| [`references.csv`](references.csv) | the register: one row per reference, with what it states and its relation to TI |
| [`landscape.md`](landscape.md) | the comparison: the families of approach, where TI sits, what it borrows, what it cannot claim |
| [`link_check.csv`](link_check.csv) | generated by `script/reference/check_references.py`: what each link returned and when |

## What is in the register

| column | note |
|---|---|
| `key` | short slug, used to cite the reference from the methodology documents |
| `family` | which approach it belongs to; the families are defined in [`landscape.md`](landscape.md) |
| `title`, `publisher`, `year`, `edition` | the reference itself, as published |
| `url`, `doi` | where it is. A DOI is given where one exists, because publisher URLs move |
| `access` | `free`, `registration` or `paywalled` — what a reader needs to open it |
| `what_it_states` | what the document says in its own terms, not what we make of it |
| `relation_to_ti` | what TI shares with it and precisely where TI departs. This is the column the register exists for |
| `cited_in` | the methodology document and section that leans on it |

## The rules this directory follows

**No copies.** These are third-party publications and the repository does not redistribute them.
`link_check.csv` records what each link returned, and `check_references.py --download` will pull
the files into `reference/cache/`, which git ignores, for anyone who wants the editions on disk.

**Every link is checked, and a dead one fails the run.** A reference with a DOI is checked
against the DOI system's own handle API rather than by scraping the publisher: Wiley, Science,
Annual Reviews and OECD iLibrary all answer an automated request with 403 while the article sits
there perfectly alive. A URL-only reference is fetched; a 403 from a host that answered is
recorded as a publisher refusing robots, not as a dead reference; a 404 or an unreachable host
fails the check.

```bash
.venv/bin/python script/reference/check_references.py            # check every link
.venv/bin/python script/reference/check_references.py --download # and keep local copies
```

**`relation_to_ti` is a judgement and has to read like one.** "Related work" is not a relation.
Either TI borrows something specific from the reference, or it departs from it on a stated point,
or the reference is the ground for an objection TI has to answer.

## Adding a reference

1. Check it is not already here. Extend the row rather than adding a second one.
2. Add the row to `references.csv` with a DOI where one exists.
3. Run the checker. If the link does not resolve, find one that does before committing.
4. If it changes what the methodology can claim, say so in [`landscape.md`](landscape.md) and in
   the methodology document itself — the register is where a reference lives, not where an
   argument lives.
