# reference — what else measures this, and where TI sits against it

The Trade Impact framework is not the only attempt to say something about the climate
consequence of a product after it is sold, and it is not the first to subtract a counterfactual
from an emissions figure. This directory is the record of that surrounding work: what each
approach measures, what it publishes, and precisely where TI departs from it. It exists so that
a claim in the methodology can be traced to a document a reader can open, and so that the
objections are on file before a reviewer raises them.

| file | what it is |
|---|---|
| [`references.csv`](references.csv) | the register: one row per reference, with what it states and its relation to TI |
| [`landscape.md`](landscape.md) | the comparison: the families of approach, where TI sits, what it borrows, what it cannot claim |
| `raw/` | **the documents themselves**, one file per reference key — kept locally, not in git. `raw/index.csv` is in git and is the manifest: source URL, content type, bytes, SHA-256 and the reason for every gap |
| [`link_check.csv`](link_check.csv) | generated by `script/reference/check_references.py`: what each link returned and when |

## What is in the register

| column | note |
|---|---|
| `key` | short slug, used to cite the reference from the methodology documents |
| `family` | which approach it belongs to; the families are defined in [`landscape.md`](landscape.md) |
| `title`, `publisher`, `year`, `edition` | the reference itself, as published |
| `url`, `doi` | where it is. A DOI is given where one exists, because publisher URLs move |
| `access` | `free`, `registration` or `paywalled` — what a reader needs to open it |
| `what_it_states` | what the document says in its own terms, not what we make of it |
| `relation_to_ti` | what TI shares with it and precisely where TI departs. This is the column the register exists for |
| `cited_in` | the methodology document and section that leans on it |

## The rules this directory follows

**The documents are on disk, and they stay out of git.** A bibliography of links rots, and a
claim you cannot open is a claim nobody can check, so `reference/raw/` holds the file behind each
reference, hashed, in the edition that was read. This is a reading library, not a dataset: the
files are local, `.gitignore` keeps them out of the repository, and `raw/index.csv` is the
manifest that lets anyone rebuild the same library with one command. 60 of the 83 documents are
there. The other 23 are recorded with the reason - a paywall with no open copy, a publisher that
refuses automated requests, a registration gate, or a live database that is not a document at
all - so every gap is visible and a reader knows what to do about it.

These are third-party publications with their own terms, carried per row in `access` and per file
in `raw/index.csv`. Several are free to read and not free to republish: this is the working
library for the research, not a re-publication of it.

```bash
.venv/bin/python script/reference/fetch_references.py            # fetch what is missing
.venv/bin/python script/reference/fetch_references.py --refresh  # re-fetch everything
```

**Documents behind a bot wall are fetched by hand.** Four publishers refuse every automated
request and two of them answer with a captcha, which is not something to work around. Open the
URL in a browser, save the file into `reference/raw/` as `<key>.pdf`, and run the fetcher again:
a file sitting under a reference's key is adopted, hashed and indexed like any other.

Nothing here is loaded into the database: `build_database.py` reads `data/<sector>/` and never
looks at `reference/`. These are for reading.

**Every link is checked, and a dead one fails the run.** A reference with a DOI is checked
against the DOI system's own handle API rather than by scraping the publisher: Wiley, Science,
Annual Reviews and OECD iLibrary all answer an automated request with 403 while the article sits
there perfectly alive. A URL-only reference is fetched; a 403 from a host that answered is
recorded as a publisher refusing robots, not as a dead reference; a 404 or an unreachable host
fails the check.

```bash
.venv/bin/python script/reference/check_references.py            # check every link and DOI
```

**`relation_to_ti` is a judgement and has to read like one.** "Related work" is not a relation.
Either TI borrows something specific from the reference, or it departs from it on a stated point,
or the reference is the ground for an objection TI has to answer.

**Approaches, not datasets.** This register holds the methods, standards and studies TI is
measured against. The datasets the model actually reads are registered per sector, in
`data/<sector>/registry/sources.csv` with the licence and access date, and in
`raw_files.csv` with the hash of every file on disk. Two rows here are exceptions and say so in
their relation column: the NDC registry and the IEA outlook, which the methodology cites as the
origin of the benchmark concept rather than as files it loads.

**A DOI year and a citation year can differ.** An online-first paper carries both. Put the
citation year in `year` and the other in `edition` - the checker looks in both, so a correctly
documented pair passes silently and an undocumented mismatch does not.

## Adding a reference

1. Check it is not already here. Extend the row rather than adding a second one.
2. Add the row to `references.csv` with a DOI where one exists, and a `file_url` pointing at the
   copy to download - for a journal article, the open-access copy, which
   `script/reference/fetch_references.py` will otherwise look up from the DOI.
3. Run the checker and the fetcher. If the link does not resolve, find one that does before
   committing; if the document cannot be downloaded, leave the reason in `raw/index.csv`.
4. If it changes what the methodology can claim, say so in [`landscape.md`](landscape.md) and in
   the methodology document itself — the register is where a reference lives, not where an
   argument lives.
