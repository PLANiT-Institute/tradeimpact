# PH2 — Research record: database and dashboard

## Purpose

PH1 proved a result can be computed and recomputed. It did not make that result **inspectable**.
Today, answering "where does this number come from" means reading five JSON files, an adapter, a
snapshot and a Korean-language status document. PH2 turns the published set into a queryable
research record in which every figure sits one join away from the source row or the numbered
assumption behind it, and puts a generated dashboard over it so a reader who runs no code sees the
same numbers the engine produced.

This is a governance phase, not an analysis phase. It produces no new TI figure.

## Objectives

1. A SQLite research database, built from the pinned snapshots and the published JSON, in which
   every published figure resolves to a `source_id` row or a numbered assumption id — verifiable by
   query, not by reading prose.
2. Referenced inputs modelled as first-class rows: value, unit, key (country / year / model /
   powertrain), source, tier, derivation, and reference year — the five-column discipline of
   `docs/rebuild-spec.md` §1 made relational.
3. Missing values represented as NULL **with a reason column**, never 0 and never absent from the
   table (`C-05`).
4. A generated HTML dashboard over the database, with no hand-typed number anywhere and no status
   prose that the data cannot contradict.
5. One home per fact: the interim spreadsheet audit (`data/TI_integrated_audit.xlsx`) becomes a
   generated export of the database or is retired.

## Entry criteria

- PH1 exit criteria all met (they are).
- `data/published/*.json` current and `check_published.py` passing.
- Every source in the published set has a `source_id` row in `sources.json` — the join key the
  database depends on.

## Exit criteria

- [ ] Database builds from a clean checkout with one documented command, from pinned snapshots only.
- [ ] Every numeric fact in `data/published/` appears in the database with a non-null provenance
      reference (`source_id`, or an `A-nn` assumption id from
      [`../toolbox/data/assumptions.md`](../toolbox/data/assumptions.md)).
- [ ] Every withheld or missing input appears as a row with a reason, not as an absence.
- [ ] Dashboard regenerates and contradicts nothing in `data/published/` — checked by the same
      derived-label discipline that closed the web drift in PH1.
- [ ] `check_published.py` still passes after the build (PH2 must not perturb the published set).
- [ ] The spreadsheet audit is either generated from the database or gone.
- [ ] No hand-written status prose in the dashboard: every state string derived from data.

## Traceability

Discharges `C-07` (reproducibility) and `W-15` (mandatory transparency fields) by making them
queryable; serves `W-14` tier declaration and `C-03` target-hierarchy disclosure by giving each a
column instead of a paragraph. Prerequisite for `D-04`…`D-07` reporting: from PH3 onward, a figure
that cannot be resolved in the database is not publishable.

## What would invalidate this phase

- The published JSON not being a complete record of the inputs — if the database build finds
  figures that exist only inside adapter code, the fix belongs in ST02/ST01, not in the schema, and
  PH2 goes back a stage.
- A schema that stores derived results as if they were observations. The three evidence layers
  (`C-02`) must remain distinguishable in the table structure; collapsing them would make the
  database a more convincing version of the error it exists to prevent.
